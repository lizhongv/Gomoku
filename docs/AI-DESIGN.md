# AI 设计

> 适用版本：v2.0.0（开发中）
> 基准数据见 [benchmarks/AI-BENCHMARK.md](benchmarks/AI-BENCHMARK.md)

## 一、目标

- 普通玩家在 4～6 档能获得势均力敌的对局，8 档以上需要认真思考。
- 不做「只会进攻」的引擎：防守与进攻使用同一套威胁评估，先看对手成五再考虑自己的组合。
- 结果可复现：固定随机种子，同一局面与同一限制得到同一步。

## 二、评估

### 2.1 棋型分值

| 棋型 | 分值 | 含义 |
| --- | ---: | --- |
| 五连 | 10,000,000 | 已经获胜 |
| 活四 | 1,000,000 | 两个成五点，无法防守 |
| 冲四 | 100,000 | 一个成五点 |
| 活三 | 50,000 | 再一手成活四 |
| 眠三 | 5,000 | 再一手只能成冲四 |
| 活二 | 500 | 再一手成活三 |
| 眠二 | 50 | 再一手成眠三 |

### 2.2 组合威胁

单点四个方向合并后额外加分：

| 组合 | 加分 | 原因 |
| --- | ---: | --- |
| 双四 | +500,000 | 对手只能堵一个成五点 |
| 四三 | +300,000 | 四逼迫对手，三再成活四 |
| 双活三 | +150,000 | 对手堵一个，另一个成活四 |

### 2.3 局面分

对每个候选空点分别计算「己方在此落子的威胁」与「对方在此落子的威胁」，
`局面分 = Σ己方 - 1.05 × Σ对方`，并逐点截断到 ±9 亿，保证低于胜负分。防守权重略大于 1，
避免引擎为了进攻放掉对手的成五点。

## 三、搜索

1. **立即胜负**：自己若能一手成五，直接走；否则若对手有成一五点，必须堵。
2. **VCF**：只考虑能形成四的进攻着法，对手被四逼迫只能堵；若形成活四或双四直接判胜。
   每层先检查对手是否已有成五点（对手会先赢），再判断「活四即胜」，避免误判。
3. **迭代加深**：深度 2、4、6……每层从排序后的候选中逐着搜索；
   超时抛出异常，`finally` 撤销所有落子，返回上一层已完成的结果。
4. **α-β**：置换表命中时按 EXACT / LOWER / UPPER 处理；Killer 与历史启发作排序补充。
5. **叶子评估**：直接调用评估函数，不做静态搜索（quiescence）；四、三的延伸由 VCF 与较深层数覆盖。

### 已知取舍

- 未实现 VCT（连续活三）搜索：VCT 分支因子远大于 VCF，需要更严格的威胁空间约束，列为后续增强。
- 未使用位棋盘与增量评估：当前实现以可读性优先，节点速度约 0.8 万/秒；
  阶段二会先做走法生成与评估缓存，再评估是否需要位棋盘。
- PVS 目前是「全窗口 α-β + 迭代加深」，未加入零窗口试探；文档与代码以实际实现为准。

## 五、实测

测试环境：Windows 11、JDK 17、单线程，开发机。数据为单次运行，会随机器的负载波动。

| 项目 | 结果 |
| --- | --- |
| 战术题库 | 50/50（一手胜 16、一手防 16、VCF 18） |
| 自对弈 8 档 vs 4 档 | 19 胜 1 负，胜率 95%（20 局，双方各执黑一半） |
| 固定局面 500 ms | 3840 节点，约 0.74 万节点/秒，完成深度 4 |
| 每步耗时（100 ms 预算） | P50 110 ms，P95 127 ms（软预算，含排序与 VCF 开销） |

**口径说明**：战术题库与自对弈都是构造局面，不代表对人类的胜率；「档位」是引擎内部强度分级，
不是官方段位。要给出可信的棋力结论，需要在 Gomocup 等公开引擎上跑基准，列为后续工作。

## 六、提示与复盘

`analyze(board, side, topN, limits)` 返回前 N 个候选及其评分，界面可用于：

- 提示：显示 1～3 个推荐点与主变；
- 复盘：逐手比较实际着法与引擎推荐，标注失误等级；
- AI 教练：解释「为什么这里要防守」时，可用候选分差与威胁类型。

## 七、测试

- 单元测试：一手胜、一手防、VCF、时间预算、禁手规避、超时后棋盘不变（回归）。
- 战术题库：50 题，覆盖四个方向、平移与镜像。
- 自对弈：`SelfPlayExperiment` 支持命令行对比两组限制，用于调参。
- 基准入口：`BenchmarkMain`，输出 Markdown 报告。
